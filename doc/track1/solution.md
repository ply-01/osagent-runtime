# OSAgent Runtime：操作系统智能体开发运行平台

参赛赛道：开源基础软件与解决方案。正式申报信息单独保存在提交材料中，不把私人联系方式写入源码。

平台以 Agent 运行时、工具协议、事件轨迹、长期记忆和 MCP / HTTP 接入交付软件能力。
制造运维交接展示核心记忆模块，不将仿真样例包装为完整生产工厂系统。

## 背景与行业需求

制造运维的知识交接会跨班次、跨会话持续发生。维护流程发生变更时，
只检索旧聊天或文档片段可能返回已失效流程；仅覆盖当前记录又难以解释修改来源。
本项目以设备维护流程为公开仿真场景，将维护知识保存为可更新、可追溯的结构化事实。
真实客户的需求访谈、部署证明和收益数据尚未提供，不声明已有真实制造客户案例。

## 技术架构

AgentLoop 管理有界规划、工具调用与事件；AgentMemoryModule 提供 remember、update、
recall、forget 接口；CoreMemoryStore 保存当前事实，Archival 保存被替代版本与历史证据，
STM 保存短期状态。检索支持结构过滤、词法和可选语义路径，使用 RRF 汇聚候选。
MCP 和 HTTP 服务复用后端，Open WebUI 是可选第三方交互层。

公开演示直接调用记忆接口，不使用模拟替代存储。它不涉及自动控制真实设备，
也不直接向生产机器下发维护指令。样例由结构化字段明确表达更新意图；
自然语言抽取性能是独立问题，不能由该演示推断。

## 核心差异与自主实现边界

1. 事实带来源、证据、版本关系与作用域。流程更新时保留被替代版本，使当前状态和审计记录并存。
2. 记忆以独立后端向 Agent Host 提供服务，接口与前端解耦，便于模型或 UI 更换。
3. 分层记忆、按查询检索和上下文压缩限制长期任务的上下文增长。
4. 银河麒麟系统 Embedding 与自有 C++ bridge 提供可选国产系统适配，需目标机单独验收。

RRF、MCP、Open WebUI 和第三方 Embedding 模型不属于本项目原创。
`mem0_*` 文件名表达记忆组织方式，不能据此认定与 Mem0 官方 SDK 相同；
原始实现来源仍需维护者核实。系统级组合价值应通过具体工作流与对比验证表达，
不宣称基础算法首创或全面领先同类项目。

## 公开验证与复现

执行 README 中的安装命令，再运行 `os-agent track1 --scenario examples/track1/maintenance-handover.json`。
公开样例验证跨存储实例持久化、同设备流程更新、旧版本追溯、设备实体区分和注销后物理遗忘。
每次生成独立状态目录、逐步 JSON 与 HTML 证据，失败检查使命令返回非零退出码。

用实体和作用域表达组织边界，样例中的实际存储身份会规范化为 `entity::scope`。
历史查询和遗忘使用规范化身份；它不是服务鉴权或多租户权限证明。
完整回归测试验证现有接口及新入口。提交者可附本机运行报告和平台信息供评审复核。

本次仿真采用离线词法检索，没有测量语义检索质量、大规模性能或自然语言抽取准确率。
样例通过率只表明这组显式工作流检查通过，不作为主办方分数线或真实业务收益。
旧专项赛历史报告及私有评测入口不包含在精简公开交付文档中，也不作为本次重新验证的结果。

## 部署、风险与后续验证

Python 核心可跨平台运行；麒麟 SDK 与完整 Open WebUI 为可选扩展。
目前主要采用本地文件持久化，面向多进程并发、崩溃恢复和多租户服务需进一步验收。
备份、访问控制、真实客户数据授权和需求收益证明应由试点补充。
长期维护、社区流程及版本规划见 GOVERNANCE、CONTRIBUTING 和 ROADMAP。
